# GPT Image 2 Quality Design

## Goal

Improve the quality and consistency of images generated by agent image tools while staying compatible with the current public GPT Image API surface. `gpt-image-2` should be supported as a deploy-time model string through configuration, but the runtime must not depend on model-specific private parameters.

## Context

Agent image generation currently flows through `image_gen_oai` and `image_edit_oai`.

- Runtime tool implementation: `api/app/clients/tools/structured/OpenAIImageTools.js`
- Tool schemas and model-facing descriptions: `packages/api/src/tools/toolkits/oai.ts`
- Tool loading, context injection, and image quota wrapping: `api/app/clients/tools/util/handleTools.js`
- Generated image artifact persistence: `api/server/controllers/agents/callbacks.js`
- Current environment documentation: `.env.example`

The current implementation already allows `IMAGE_GEN_OAI_MODEL` to override the image model, and tests verify that model value is passed through. The missing layer is a quality policy that consistently applies high-quality defaults, keeps generation and editing aligned, and handles multiple returned images.

OpenAI's current public image guidance lists configurable output options for GPT Image: size, quality, output format, output compression, and background. The current tool already uses these fields for generation, so the design should refine defaults and validation rather than replace the API path.

## Options Considered

### Option 1: Configuration-only change

Document `IMAGE_GEN_OAI_MODEL=gpt-image-2` and rely on operators to ask agents for high quality in prompts.

This is the smallest change, but quality remains inconsistent because the model can call the tool with `auto` or omit quality and size.

### Option 2: New high-quality tool

Add a separate `image_gen_oai_hq` tool with stricter defaults.

This makes the high-quality behavior explicit, but it adds tool selection ambiguity and requires changes to agent tool selection, permissions, quotas, UI labels, and tool expansion.

### Option 3: High-quality defaults in the existing OpenAI image toolkit

Keep `image_gen_oai` and `image_edit_oai`, and add a configuration layer that normalizes defaults before sending requests.

This is the recommended option. It preserves existing agents, quotas, file rendering, and UI behavior while making high-quality generation the default for deployments that opt in.

## Recommended Design

Add an OpenAI image option resolver inside `OpenAIImageTools.js`. The resolver should merge values in this order:

1. Explicit tool-call argument.
2. Environment default.
3. Existing safe fallback.

The supported environment defaults are:

- `IMAGE_GEN_OAI_MODEL`, defaulting conservatively to the existing `gpt-image-1` unless a migration explicitly changes it.
- `IMAGE_GEN_OAI_QUALITY`, recommended value `high`.
- `IMAGE_GEN_OAI_SIZE`, recommended value `1024x1024` or `auto`.
- `IMAGE_GEN_OAI_BACKGROUND`, recommended value `auto`.
- `IMAGE_GEN_OAI_OUTPUT_FORMAT`, optional override for generation output format.
- `IMAGE_GEN_OAI_OUTPUT_COMPRESSION`, recommended value `100` for JPEG and WebP output.

The resolver must only emit fields supported by the current public Images API request shape:

- `model`
- `prompt`
- `n`
- `background`
- `output_format`
- `output_compression`
- `quality`
- `size`

No `gpt-image-2`-specific private parameters should be added. If a deployment sets `IMAGE_GEN_OAI_MODEL=gpt-image-2`, the model name is passed through using the same official parameter set.

## Data Flow

For `image_gen_oai`, the agent supplies a prompt and optional image options. The tool resolver normalizes the options, applies the configured model, and calls `openai.images.generate`.

For `image_edit_oai`, the agent supplies image IDs, prompt, and optional image options. The same resolver should provide quality and size defaults for the edit request so edits do not silently drop to lower-quality defaults.

After the OpenAI response returns, the tool should iterate over every returned image item instead of reading only `resp.data[0]`. Each item with `b64_json` becomes one `image_url` artifact and one generated file ID. The visible text response should include all generated image IDs so later edit calls can reference any of them.

## Error Handling

Keep the current API error path and user-facing generic tool failure behavior.

Add validation around environment defaults:

- Unknown `quality`, `size`, or `background` values fall back to current safe defaults and log a warning.
- `output_compression` is clamped to `0..100`.
- `n` remains clamped to `1..10` for generation and quota accounting.
- Transparent background continues to force PNG or WebP output when the configured format is incompatible.
- If no returned image contains `b64_json`, return the existing "No image data returned" message.

## Testing

Add focused Jest tests under `api/test/app/clients/tools/structured/OpenAIImageTools.test.js`:

- Defaults to the existing model when `IMAGE_GEN_OAI_MODEL` is unset.
- Passes through `IMAGE_GEN_OAI_MODEL=gpt-image-2` without adding non-public parameters.
- Applies env defaults for quality, size, background, output format, and compression.
- Lets explicit tool-call arguments override env defaults.
- Clamps invalid `n` and `output_compression` values.
- Returns multiple image artifacts and file IDs when the API returns multiple `b64_json` values.
- Applies the same quality and size defaults to `image_edit_oai`.
- Preserves transparent-background format correction.

Keep existing quota tests in `api/app/clients/tools/util/handleTools.test.js` passing because the tool names and quota wrapper stay unchanged.

## Documentation

Update `.env.example` with the new high-quality image settings and examples:

```env
# IMAGE_GEN_OAI_MODEL=gpt-image-2
# IMAGE_GEN_OAI_QUALITY=high
# IMAGE_GEN_OAI_SIZE=1024x1024
# IMAGE_GEN_OAI_BACKGROUND=auto
# IMAGE_GEN_OAI_OUTPUT_FORMAT=png
# IMAGE_GEN_OAI_OUTPUT_COMPRESSION=100
```

Document that `gpt-image-2` is a configurable model string and that runtime compatibility is maintained by using only the public GPT Image parameter set.
